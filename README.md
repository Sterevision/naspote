# Картометр 📍

**kartometr.ru** — карта, а не лента. Оставляешь метку — где ты и что тут происходит — и это как будто
приглашение для друзей заглянуть. Публично или только для своих.

> Обновление: приложение переименовано из «На споте» в «Картометр» под новый домен.
> Все таблицы, миграции и файлы в базе остались без изменений — переименование чисто
> на уровне интерфейса и текстов, схему БД трогать не нужно.

Стек: **Python (Flask)** для сервера + **Supabase** (Postgres, Auth, Storage) как база.
Всё крутится у тебя на ПК, база — в облаке Supabase (бесплатный тариф хватит с запасом).

## 1. Создай проект в Supabase

1. Зайди на [supabase.com](https://supabase.com) → **New project** (бесплатно).
2. Дождись, пока проект поднимется (1–2 минуты).
3. В левом меню открой **SQL Editor** → **New query**.
4. Скопируй туда содержимое файла `supabase_schema.sql` из этого проекта и нажми **Run**.
   Это создаст таблицы `profiles`, `spots`, `friendships`, политики безопасности (RLS)
   и хранилище для фото `spot-photos`.
5. Зайди в **Project Settings → API** и скопируй:
   - `Project URL` → это `SUPABASE_URL`
   - `anon public` key → это `SUPABASE_ANON_KEY`

### Важно про подтверждение email
По умолчанию Supabase требует подтверждения почты при регистрации.
Для локальной разработки удобнее это отключить:
**Authentication → Providers → Email → Confirm email → выключить.**
Тогда регистрация будет сразу давать доступ, без письма на почту.

### Если у вас уже был запущен supabase_schema.sql раньше
Появились новые возможности — они требуют новых колонок в базе. Откройте
**SQL Editor** и по очереди выполните `supabase_migration_v2.sql`, затем
`v3.sql`, `v4.sql`, `v5.sql`, `v6.sql`, `v7.sql`, `v8_security.sql`,
`v9_conversations.sql`, `v10_final_fixes.sql`, `v11_profile_chat_comments.sql`,
`v12_notifications.sql` — это безопасные добавочные миграции, они ничего не
удаляют и не ломают существующие данные.
Если вы разворачиваете проект с нуля — выполните по порядку:
`supabase_schema.sql` → `v2` → `v3` → `v4` → `v5` → `v6` → `v7` →
`v8_security` → `v9_conversations` → `v10_final_fixes` →
`v11_profile_chat_comments` → `v12_notifications`.

⚠️ **v7–v12 обязательны, а не опциональны.** Без них приложение либо не
запустится, либо будет работать некорректно/небезопасно:
- без **v9/v10** нет функции `get_conversations()` — `/api/conversations`
  (список чатов) всегда возвращает ошибку 400;
- без **v10** нет RLS-политики `messages_insert_friend` — старая политика
  из v6 разрешает писать сообщения кому угодно, а не только друзьям;
- без **v11** в таблице `messages` нет колонки `image_url`, а `profiles`
  не имеет `home_lat/home_lng/home_location_name/telegram_username/
  contact_phone/contact_email` — отправка фото в чат и настройки контактов/
  домашней точки будут падать с ошибкой;
- без **v12** нет функции `mark_all_messages_read()` и поля `friends_seen_at`;
- без **v8** отсутствуют многие RLS-политики и ограничения (`can_view_spot`,
  анти-фарм XP, лимиты длины полей) — часть API из `app.py` полагается на
  них и без v8 либо не сработает, либо будет менее защищена.

Что даёт каждая миграция:
- **v2** — аккаунты организаций, ручная расстановка меток, привязка метки к заведению
- **v3** — срок жизни метки (авто-исчезновение), storage для аватаров/обложек
- **v4** — категория метки, персональный фильтр карты по категориям
- **v5** — геймификация: XP, уровни, значки/достижения, волны (временные события),
  голосовые метки, совместные метки (первая версия — заменяется v8)
- **v6** — «место обитания» в профиле, комментарии к меткам, личные сообщения
- **v7** — `telegram_id` для входа через Telegram Mini App
- **v8** — усиление безопасности: RLS-политики на все таблицы, `are_friends()`,
  `can_view_spot()`, анти-фарм XP, ограничения длины полей, индексы
- **v9 / v10** — чат только между друзьями (RLS `messages_insert_friend`) и
  функция `get_conversations()` для списка диалогов (используется в `app.py`
  и `messages.js`)
- **v11** — домашняя точка на карте, контакты (telegram/телефон/email),
  картинки в личных сообщениях + bucket `chat-images`
- **v12** — счётчик непрочитанных заявок в друзья (`friends_seen_at`),
  функция `mark_all_messages_read()`

## 2. Установи и запусти приложение

Нужен Python 3.10+.

```bash
cd naspote
python -m venv venv
source venv/bin/activate        # на Windows: venv\Scripts\activate

pip install -r requirements.txt

cp .env.example .env            # на Windows: copy .env.example .env
```

Открой `.env` и вставь свои значения:

```
SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
SUPABASE_ANON_KEY=eyJhbGciOi...
FLASK_SECRET_KEY=придумай-любую-случайную-строку
```

Запусти сервер:

```bash
python app.py
```

Открой в браузере: **http://localhost:5000**

## 3. Что уже работает

- Регистрация / вход через Supabase Auth, два типа аккаунта: **человек** и **организация**
- Карта (Leaflet + OpenStreetMap, бесплатно, без API-ключа) в тёмной теме
- Метка по геолокации ("Оставить метку") или **вручную по клику на карте** (кнопка ✋) —
  ручные метки визуально выделяются жёлтым пунктиром
- Привязка метки к конкретному заведению — актуально, если в одном здании несколько
  заведений: при создании метки можно найти и выбрать заведение из тех, что рядом
- **Категория метки** (бар, вечеринка, выставка, природа и т.д.) — используется для
  персональных фильтров карты
- **Срок жизни метки**: при создании выбирается, на сколько часов её показывать
  (1–24 ч) — по истечении она автоматически перестаёт быть видна на карте
- **Лимит "одна активная метка"**: у обычного пользователя (не заведения) в любой
  момент может быть только одна метка — публикация новой автоматически убирает старую
- **Личный кабинет** (⚙️ Настроить на странице профиля): смена имени, аватара, описания,
  для заведений — категории, адреса, обложки страницы
- **Персональный фильтр карты**: в личном кабинете можно выбрать, метки каких категорий
  показывать (например, только бары и выставки) — свои метки и метки без категории
  видны всегда
- Публично / только для друзей
- Легенда цветов меток (кнопка 🎨 на карте)
- Заявки в друзья, поиск по username, принятие/отклонение
- Профиль с лентой из своих меток (сеткой, как публикации)
- **Страница заведения**: обложка, категория, адрес, отметка верификации,
  отдельные ленты "публикации от заведения" и "люди отмечались здесь"

### Как работают аккаунты организаций
При регистрации заведение выбирает "Я — заведение" и получает свою страницу
(`/profile/username`) с иной вёрсткой: обложка, категория, адрес. Управление
страницей происходит через личный кабинет (⚙️ Настроить) — можно сменить
обложку, аватар, категорию и адрес. Заведение может оставлять свои метки —
на них лимит "одна активная метка" не действует. Когда обычный пользователь
ставит метку и привязывает её к этому заведению — она появляется в ленте
"Люди отмечались здесь" на странице заведения.
Верификацию (галочку ✅) администратор пока проставляет вручную в Supabase:
таблица `profiles`, поле `is_verified`.

### Как работает автоудаление меток по таймеру
При создании метки автор выбирает срок жизни (1–24 часа). Метка хранит
`expires_at`, и при каждом запросе списка меток (`/api/spots`) сервер:
1. лениво удаляет из базы уже истёкшие метки текущего пользователя
   (RLS разрешает удалять только свои строки анонимным ключом);
2. отфильтровывает чужие истёкшие метки, даже если их ещё не успели удалить.
Из-за использования анонимного ключа полное фоновое удаление чужих истёкших
меток (например, ночью, когда никто не заходит) не реализовано — если нужно
именно физическое удаление вне зависимости от активности пользователей,
потребуется добавить service-role ключ и APScheduler/cron задачу.

## 3.1 Что было починено в этой версии

- **Заявки в друзья реально работают.** Раньше кнопки «Добавить в друзья» / «Принять»
  дёргали несуществующие роуты и падали в 404. Добавлены
  `POST /api/friends/<username>/add`, `POST /api/friends/<id>/accept`,
  `POST /api/friends/<id>/decline`, `DELETE /api/friends/<id>`.
- **Личные сообщения превратились в настоящий чат.** Раньше `/messages` вёл на список
  друзей, у которого кнопки открывали профиль вместо переписки. Теперь есть
  `/messages/<username>` — экран чата с автообновлением.
- **Регистрация и настройки заведений реально сохраняют категорию/адрес/координаты** —
  раньше форма их не показывала, хотя сервер их принимал. Добавлена геолокация одним тапом.
- **Личный фильтр карты по категориям** — чекбоксы в настройках теперь на месте
  (раньше `visible_categories` нечем было отредактировать).
- **CSS полностью пересобран** под фактическую вёрстку — раньше добрая половина
  классов в шаблонах (`.card`, `.list-page`, `.row-card`, `.big-add`, `.btn-green`...)
  не имела стилей вовсе.
- Профиль с `account_type=organization` больше не теряет свои поля при сохранении
  настроек (в форме не хватало скрытого `account_type`, из-за чего бэкенд не понимал,
  что сохранять).

## 3.2 Новые «фишки» — включён весь ранее «немой» функционал БД

Это всё уже было в схеме и в `app.py`, но не имело интерфейса:

- **Волны (⚡)** — переключатель в форме метки: длительность, лимит людей,
  пульсирующее кольцо на карте, кнопка «Я тоже здесь» и живой список участников.
- **Голосовые заметки** — запись прямо в браузере (15 сек), проигрыватель в карточке метки.
- **Привязка метки к заведению** — поиск заведений рядом, автоматический social proof
  («сегодня здесь были 12 человек, из них 3 друга») в карточке метки.
- **Ручная расстановка меток** — тап по карте в специальном режиме, метка помечена жёлтым.
- **XP, уровень и бейджи** — виджет на странице профиля, читает данные из
  `user_achievements`, которые уже начисляет SQL-триггер `award_spot_xp`.
- **Категории** — фильтр-скроллер над картой + выбор категории при создании метки.
- **Бейдж непрочитанных** — точка на вкладках «Друзья»/«Чаты» в нижней навигации.

## 4. Что можно добавить дальше

- Push/веб-уведомления, когда друг оставил метку рядом с тобой
- Полноценный фоновый cron для удаления истёкших меток даже без активных пользователей
- Комментарии/реакции под меткой
- Загрузка нескольких фото на метку
- Панель управления для заведений (статистика по дням)
- Мобильная упаковка (PWA) — сайт уже адаптивный и мобильный по вёрстке
